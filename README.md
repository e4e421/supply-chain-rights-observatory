# Supply Chain Rights Observatory

Public, source-traceable research intelligence for **European supply chain sustainability, human rights, labour standards and responsible procurement**.

**Website:** https://e4e421.github.io/supply-chain-rights-observatory/

## Contents

- `/docs`: static, mobile-friendly research site.
- `/docs/data/latest.json`: public research leads (generated by Actions).
- `/docs/data/references.json`: manually curated authoritative sources and their research use.
- `/docs/data/archive-summary.json`: permanent public record counts; `/docs/data/source-health.json`: source review status.
- `/sources/queries.json`: public keyword monitoring configuration.
- `/sources/registry.json`: editorially curated source register (17 sources at initial migration); `/sources/candidates.json`: queue for editorial review.
- `/data/archive/YYYY-MM.jsonl`: permanent public-metadata-only monthly archive; `/data/archive/manifest.json`: counts, partition digests.
- `/data/events/curated.json`: manual event linkage scaffold, empty until verified case assessments exist.
- `/scripts/update_data.py`: RSS, Crossref and OpenAlex collector (Python standard library only).
- `/scripts/archive_data.py`: stable ID verification, idempotent monthly archiving and SHA-256 manifest.
- `/scripts/source_governance.py`: source integrity registry, quarterly review reminders and weekly domain-restricted HTTPS reachability checks.
- `/scripts/export_archive_csv.py`: offline English-schema CSV export with spreadsheet-injection protection.
- `/scripts/validate_data.py`: fail-closed JSON/schema/URL checks.
- `/tests`: offline unit tests using local fixtures.
- `/.github/workflows/refresh-and-publish.yml`: scheduled refresh, validation and Pages deployment.
- `/SECURITY.md`: security model, threat boundaries and recommended account settings.


## Multilingual research interface (English canonical)

The research portal supports **English (default)**, **Traditional Chinese**, **German**, and **Spanish**. User-visible copy is authored in English, with audited translation mappings in `docs/i18n.js`. The public feed's source names and descriptions are generated in English, and legacy Chinese records remain readable through backwards-compatible display aliases.

- Switch using the header selector, or share links with `?lang=en`, `?lang=zh`, `?lang=de` or `?lang=es`. Language choices are saved locally in the browser.
- The page language and date formatting adapt to the selection. The site displays timestamps and filters publication dates in **UTC**.
- Original newspaper and academic publication titles remain in the language in which they were published.
- UTF-8 CSV downloads retain canonical English field names, stable topic identifiers and original titles for reproducible collaborative analysis.
- Static site copy, source descriptions, live status messages, research themes and source cards are translated. The collection workflow remains language-independent.


## Two public fronts: visitor portal and professional workbench

- **Visitor portal:** https://e4e421.github.io/supply-chain-rights-observatory/ — introductory research context, latest headlines, references, historical archive, methods and limitations.
- **Professional workbench:** https://e4e421.github.io/supply-chain-rights-observatory/workbench/ — search the combined index, narrow results by publication date (UTC), and sort by first observation to see recently collected records. The workbench also supports AND/OR/phrase queries, DOI and record ID lookup, and publication provenance. Use the [Research Archive](https://e4e421.github.io/supply-chain-rights-observatory/archive/) to browse by first-observation month and the [Source Directory](https://e4e421.github.io/supply-chain-rights-observatory/sources/#data-availability) for feed and reference availability.
- Bookmark \`/workbench/\` for a fast daily research entry. Shared URLs retain filters. Named views are stored in the current browser.
- Keyboard controls: \`/\` to focus search, \`J/K\` to navigate records, \`Enter\` to inspect the selected record, and \`Escape\` to clear selection. Dense and comfortable table modes are available.
- **Combined archive search:** monthly static JSON shards are loaded on demand. A conservative 24-shard / 10,000-record browser limit prevents runaway loads; when exceeded, the interface explicitly labels results as **partial**. The canonical JSONL remains the research-grade export source.
- CSV export contains filtered publication metadata with stable English column names and spreadsheet-injection protection.
- Both views share the same GitHub Pages static deployment.

## Manual setup (one-time)

1. Open **[GitHub repository Settings → Pages](https://github.com/e4e421/supply-chain-rights-observatory/settings/pages)**.
2. Under **Build and deployment → Source**, select **GitHub Actions** (not **Deploy from a branch**), then save if prompted. This is important: commits made with the GitHub Actions `GITHUB_TOKEN` do not automatically trigger Pages branch publishing.
3. Open **[Actions](https://github.com/e4e421/supply-chain-rights-observatory/actions)**. If Actions are disabled, enable them for this repository. Select **Refresh public intelligence and deploy** → **Run workflow** → `main` → **Run workflow**.
4. Check that the `collect` and `deploy` jobs finish successfully. The initial collection needs access to external sources; partial source failures show a warning and are not silently treated as complete coverage.
5. View the site at **https://e4e421.github.io/supply-chain-rights-observatory/** or use **Settings → Pages → Visit site**. It can take several minutes for the initial deployment.
6. Optional but recommended: **Settings → Actions → General**: use least-privilege workflow permissions; review **SECURITY.md** and protect your account with 2FA.

Data collection is scheduled daily at **10:23 and 22:23 UTC**. On Sundays at **22:43 UTC**, an additional collection includes source link checks for approved institutional URLs. The website reports the timestamp of the last successful collection. Each collection also reads the European Commission Press Corner, the EUR-Lex Official Journal L feed, and the Eurostat social-statistics release feed. It keeps original titles, release dates, publisher attribution and links for matching publications. The source directory links the applicable metadata reuse notices. To refresh the feeds and check reference links immediately, run the workflow with `deploy_only` turned off. A main-branch commit titled `Refresh public source feeds: …` also starts a collection and reference check.

## Long-term research database and source governance

The daily collection workflow appends newly accepted records to the permanent archive, grouped by first-observation month. The collection snapshot retains up to 240 records published within the past 150 days and supplies the latest research section on the homepage.

- One immutable first-observation entry per `record_id` in `data/archive/YYYY-MM.jsonl`; stable IDs use the existing 18-character public SHA-256 prefix. Collision/fingerprint mismatches fail closed. Each record has `first_seen` and `event_id: null`.
- `manifest.json` enumerates monthly files with SHA-256 digests, sizes and record counts. **Integrity checks are not authenticated third-party signatures**; project administrators can still alter history.
- Assign `event_id` through a separately reviewed case assessment.
- Source registry tracks `verified_on`, `review_due`, methodological provenance and approval status. The source directory shows review dates and upcoming reviews.
- Weekly availability tests use HTTPS HEAD and a hard-coded host allowlist. The source directory records the latest outcome and consecutive failures. Source approvals follow editorial review.
- At least quarterly, manually review institutional status, editorial independence, dataset revisions, data rights and methods, source links, false positives and event coverage.
- On-demand local CSV: `python3 scripts/export_archive_csv.py --output /tmp/scro-public-archive.csv`; English field identifiers remain stable for R, Python, DuckDB and Excel.
- Monthly off-repository backups to an access-controlled storage location are recommended. GitHub commit history alone is not adequate for disaster recovery.

See [data architecture](docs/ARCHITECTURE.md) and [source issue templates](.github/ISSUE_TEMPLATE/new-source.yml).

## Data integrity and research interpretation

- **Discovery feeds**: Google News RSS supplies article titles, publication dates and source links.
- **Academic metadata**: Crossref and OpenAlex supply bibliographic records. Check publication versions and methods at the publisher.
- **Official documents**: CSDDD and EU Forced Labour Regulation dates are presented as **manually verified reference text**, not as machine-parsed legislation. Verify versions and national transposition before relying on them in a study.
- **Coverage**: Search ranking, language, sampling and reporting patterns shape the corpus. Incidence estimates require a defined population and sampling design.
- **Data fields**: original title, published date, link, monitoring source, evidence class, topics and DOI (where relevant).
- **When feeds fail**: previously captured leads up to 150 days old are retained. The status becomes `partial` or `failed`, and the site clearly warns if the last successful collection becomes stale.
- **Download**: the website offers an Excel-compatible UTF-8 CSV; spreadsheet-formula injection is neutralized by escaping leading spreadsheet operators.

## Test locally

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_data.py
python3 scripts/validate_archive.py
python3 -m http.server 8000 --directory docs
# Open http://localhost:8000
```

The first actual network refresh is designed to run in GitHub Actions. To run it locally with public network access:

```bash
python3 scripts/update_data.py
python3 scripts/source_governance.py
python3 scripts/validate_data.py
python3 scripts/validate_archive.py
```

## Update research focus

Edit `sources/queries.json`, add or revise keywords and query descriptions. Every query is public, and is intended for **information discovery**; changes should be reviewed for bias and false positives. To propose a new source, use the [source proposal form](https://github.com/e4e421/supply-chain-rights-observatory/issues/new/choose). An editor checks original publisher authority, data method, licensing, geographic coverage and reliability before updating **both** `sources/registry.json` and `docs/data/references.json`. Changes to automated collection hosts follow a separate review.
